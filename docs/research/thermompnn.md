# ThermoMPNN: paper-to-code map

## Primary sources

**ThermoMPNN paper.** Henry Dieckhaus, Michael Brocidiacono, Nicholas Z. Randolph, and Brian Kuhlman, “Transfer learning to leverage larger datasets for improved prediction of protein stability changes,” *Proceedings of the National Academy of Sciences* 121(6), e2314853121 (2024), [doi:10.1073/pnas.2314853121](https://doi.org/10.1073/pnas.2314853121). The [full article at PubMed Central](https://pmc.ncbi.nlm.nih.gov/articles/PMC10861915/) is primary text; the authors' [ThermoMPNN README and citation](https://github.com/Kuhlman-Lab/ThermoMPNN/blob/370f76ec62bd929f7425e311d8df04a0d094990f/README.md#L1-L27) identify the official repository and paper.

**Double-mutant extension.** Henry Dieckhaus and Brian Kuhlman, “Protein stability models fail to capture epistatic interactions of double point mutations,” [bioRxiv:2024.08.20.608844v1](https://www.biorxiv.org/content/10.1101/2024.08.20.608844v1.full). The authors' [ThermoMPNN-D repository](https://github.com/Kuhlman-Lab/ThermoMPNN-D/tree/df9a75aaddb674a7c4c193005031fc0536d325fb) is the upstream source identified by this project's [README](../../README.md#L62-L97). The original ThermoMPNN README also points users to ThermoMPNN-D as the double-mutant extension ([pinned README](https://github.com/Kuhlman-Lab/ThermoMPNN/blob/370f76ec62bd929f7425e311d8df04a0d094990f/README.md#L1-L15)).

## Method details that orient the implementation

In the original paper's **Results, “ThermoMPNN Architecture,”** the model has a pretrained ProteinMPNN structure/sequence encoder and a stability head. ProteinMPNN represents backbone geometry with Gaussian radial-basis features over the 48 nearest residues; the stability head takes the mutated residue's decoder embeddings together with its wild-type sequence embedding, then predicts a stability change as

`ΔΔG°pred = ΔG°pred(mutant) − ΔG°pred(wild type)`.

The paper describes a light-attention block followed by a two-hidden-layer MLP. **Figure 1A** diagrams this flow; **Table 1** compares transfer learning with ProteinMPNN-only, no-light-attention, no-pretraining, and fine-tuned ablations. Those are useful landmarks when reading the single-mutant path ([article, Fig. 1](https://pmc.ncbi.nlm.nih.gov/articles/PMC10861915/#fig01); [Table 1](https://pmc.ncbi.nlm.nih.gov/articles/PMC10861915/#t01); [architecture text](https://pmc.ncbi.nlm.nih.gov/articles/PMC10861915/), Results → “ThermoMPNN Architecture”). The authors' pinned [`transfer_model.py`](https://github.com/Kuhlman-Lab/ThermoMPNN/blob/370f76ec62bd929f7425e311d8df04a0d094990f/transfer_model.py#L40-L114) shows the corresponding residue-state extraction and mutant-minus-wild-type readout.

ThermoMPNN-D extends that representation to mutation pairs. Its **Methods, “ThermoMPNN-D architecture,” and Figure 1A–C** describe per-site node states from the last two ProteinMPNN decoder layers, the directed edge state between mutated sites (zero when no edge is present), and the wild-type-minus-mutant sequence-embedding difference. A shared projection reduces each site's features; the two reduced vectors are concatenated in AB and BA orders and passed through the same prediction MLP. Figure 1C illustrates “over-and-back” augmentation from pairs of measured single mutants ([preprint Methods and Figure 1](https://www.biorxiv.org/content/10.1101/2024.08.20.608844v1.full#F1)).

The preprint describes a custom symmetry loss on the two order-specific outputs, but its displayed equation is embedded as an image. The executable form below is therefore transcribed from the authors' code, not quoted as a text-extracted paper equation:

```text
pavg = (pAB + pBA) / 2
psym = |pAB − pBA| / 2
L = α · MSE(pavg, y) + β · mean(psym)
```

This explicitly fits the averaged prediction to the measured target while penalizing order asymmetry ([authors' trainer at the pinned revision](https://github.com/Kuhlman-Lab/ThermoMPNN-D/blob/df9a75aaddb674a7c4c193005031fc0536d325fb/thermompnn/trainer/v2_trainer.py#L119-L148)).

## Mapping to this repository

- **Encoder and single-mutant readout:** [`v2_model.py`](../../src/mutation_prediction/thermo_mpnn_d/thermompnn/model/v2_model.py#L61-L66) constructs `TransferModelv2`; its forward pass calls ProteinMPNN and collects configured decoder states ([lines 118–141](../../src/mutation_prediction/thermo_mpnn_d/thermompnn/model/v2_model.py#L118-L141)). The standard path gathers the mutated position, builds its feature vector, and selects mutant versus wild-type amino-acid outputs ([lines 285–342](../../src/mutation_prediction/thermo_mpnn_d/thermompnn/model/v2_model.py#L285-L342)). The local code has optional/configurable feature paths, so the paper's schematic is a conceptual map, not a promise that every configuration follows the same exact path.
- **Siamese pair path:** [`v2_model.py`](../../src/mutation_prediction/thermo_mpnn_d/thermompnn/model/v2_model.py#L370-L526) implements `TransferModelv2Siamese`: it gathers site representations, optionally adds mutant sequence and directed edge features, reduces the per-site vectors, concatenates AB/BA orders, and returns both predictions. Compare the [authors' corresponding model source](https://github.com/Kuhlman-Lab/ThermoMPNN-D/blob/df9a75aaddb674a7c4c193005031fc0536d325fb/thermompnn/model/v2_model.py#L359-L535).
- **Pretrained and optional features:** [`modules.py`](../../src/mutation_prediction/thermo_mpnn_d/thermompnn/model/modules.py#L18-L54) builds ProteinMPNN from the configured checkpoint and freezes it when requested. Optional side-chain features are assembled by `SideChainModule` ([lines 313–371](../../src/mutation_prediction/thermo_mpnn_d/thermompnn/model/modules.py#L313-L371)); its coordinate/edge feature construction is in [`SideChainProteinFeatures`](../../src/mutation_prediction/thermo_mpnn_d/thermompnn/model/modules.py#L108-L200). The underlying graph-conditioned `ProteinMPNN` and PDB parsing are in [`protein_mpnn_utils.py`](../../src/mutation_prediction/thermo_mpnn_d/thermompnn/protein_mpnn_utils.py#L1204-L1307) and [lines 134–193](../../src/mutation_prediction/thermo_mpnn_d/thermompnn/protein_mpnn_utils.py#L134-L193).
- **Siamese training:** [`v2_trainer.py`](../../src/mutation_prediction/thermo_mpnn_d/thermompnn/trainer/v2_trainer.py#L119-L158) computes the two-order average, symmetry penalty, and weighted loss shown above.
- **Batch/data boundary:** [`v2_datasets.py`](../../src/mutation_prediction/thermo_mpnn_d/thermompnn/datasets/v2_datasets.py#L20-L61) allocates padded coordinates, sequence, mutation, and target arrays; [lines 256–316](../../src/mutation_prediction/thermo_mpnn_d/thermompnn/datasets/v2_datasets.py#L256-L316) populate and return the 12-tensor batch consumed by the model. The root README documents this tuple and the packaged ThermoMPNN-D lineage ([lines 62–97](../../README.md#L62-L97)).

**Scope caveats.** This repository packages a local adaptation of the upstream implementation; the links above map the checked-in files and do not assert byte-for-byte identity with the pinned upstream revision. The README also notes that the optional `double-aug` training requires mutation-specific Rosetta-modeled structures not included with the described local dataset ([README](../../README.md#L75-L82)). In this code, targets come from the dataset's `mut.ddG`; although the model's mutant-minus-wild-type output matches the original paper's stated equation, the dataset tensor comment labels its sign as “WT ddG - Mutant ddG” ([dataset line 61](../../src/mutation_prediction/thermo_mpnn_d/thermompnn/datasets/v2_datasets.py#L61)). Confirm the configured data convention before comparing signs across papers or runs.
